# Category pages

Status: **live** — generated by `tools/build-categories.mjs` into `docs/<slug>/`

Six pages, one per category, each listing the printables in it. The home page
shows the six categories instead of all 26 printables.

## Why

The home page rendered every printable in one long scroll. Three things were
wrong with that: it gave a graph-paper sheet and the calendar maker the same
weight, the only way to browse was to keep scrolling, and the page carried the
search weight for six quite different topics at once.

Splitting by category gives each group a real page with its own title,
description and URL — something to rank for "printable graph paper and grids"
rather than trying to rank the home page for everything.

## The URLs, and why they are spelled out

The slug is a separate field on each entry in `AP.CATEGORIES`, not the `id`,
because three ids make bad public URLs:

| id | slug | why not the id |
|---|---|---|
| `labels` | `cards-and-labels` | `/labels/` is already a printable's landing page |
| `home` | `home-and-life` | `/home/` reads like the site root, not a category |
| `fun` | `games-and-puzzles` | `/fun/` says nothing to someone reading the address bar |
| `calendars` | `calendars-and-planners` | too close to the `/calendar/` landing page |

The build asserts nothing here — but `tools/build-categories.mjs` and
`tools/build-landing.mjs` both write into `docs/<slug>/`, so a slug that
collided with a printable id would have one silently overwrite the other. If
you add a category, check the slug against `docs/` first.

## What they are made of

Static HTML, no JavaScript — the same bargain the landing pages make. Their job
is to answer a browse or a search and hand the visitor to a maker, and sign-in
is not part of that (see `accounts.md`).

The cards are the same design the home page draws, and the line art comes from
`docs/assets/js/art.js` so that one drawing serves both: the home page renders
category cards in the browser, the generator renders printable cards at build
time. Before this the art lived inside `home.js`, where the generator could not
reach it.

Each page carries `CollectionPage` structured data with an `ItemList` of its
printables, and links to the other five categories at the foot.

## What changed around them

- The header nav links to the six category pages instead of home-page anchors.
- Landing-page breadcrumbs point at the category page, not `index.html#<cat>`.
- The sitemap gained the six URLs, at priority 0.8 — above the makers, below
  the landing pages that target a named search.
- The home hero's third button was "See everything", pointing at `#calendars`.
  That anchor no longer exists and the home page no longer shows everything; it
  is now "Browse by category".

## Rebuilding

    node tools/build-categories.mjs   # the six category pages
    node tools/build-landing.mjs      # landing pages, and the sitemap

Run the landing build second: it writes `sitemap.xml`, which includes the
category URLs.
